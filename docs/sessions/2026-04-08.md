### 2026-04-08 — review 后 v2

第一版计划经过代码 review 发现 5 处与现状不匹配 + 2 个待定问题，已在下方"计划"小节修正。修订要点：

1. **OpenRouter 专有字段必须走 `extra_body`** —— OpenAI Python SDK 在 `chat.completions.create()` 上做 Pydantic 校验，把 `provider` / `models` 放在顶层 kwargs 会被静默丢弃。Step 1 / Step 4 改为通过 SDK 的 `extra_body` 入口注入。
2. **`max_tokens` 来源改读 `top_provider.max_completion_tokens`** —— OpenRouter Models schema 把"总上下文窗口"（`context_length`）和"输出上限"（`top_provider.max_completion_tokens`）分开两个字段；Coco 整条链路（`models.py:47` / `llm.py:104` / `llm.py:446`）的 `max_tokens` 都是"输出上限"语义，第一版误用 `context_length` 会把窗口大小当输出上限发出去。
3. **CLI argparse choices 是硬卡点** —— `main.py:195` 的 `choices=("anthropic", "openai")` 是 argparse 强制集合，光加 `Provider.OPENROUTER` 枚举不够，`coco --provider openrouter` 会被命令行直接拒绝。同时 `main.py:158` 和 `commands.py:476` 写死的"请设置 ANTHROPIC_API_KEY 或 OPENAI_API_KEY"提示也要更新。
4. **`fallback_models` 必须 gate 在 OpenRouter 路径** —— `_OpenAIBackend` 同时承载 OpenAI / DashScope / Qwen / vLLM 等所有 OpenAI 兼容网关，第一版把 `fallback_models` 沿通用路径下传会让 DashScope/Qwen 用户的请求里凭空多出 `extra_body["models"]` 字段。改为只在工厂层针对 `Provider.OPENROUTER` 注入"开关"，普通 `provider=openai` 路径默认 False。
5. **成本回显从本计划拆出** —— Coco 当前 `main.py:340-364` 拿到 `result = engine.run(...)` 后**完全没有消费 `result.usage`**，没有任何 token / 成本显示代码。在 OpenRouter PR 里加 `cost_usd` 字段没有展示面；这一步独立成另一份 session 文档，先把"REPL token 累计显示"做出来才有载体。
6. **缓存路径走 `paths.py` 的 XDG 约定** —— 第一版写死 `~/.coco/`，实际 Coco 已经统一用 `data_home() / "openrouter_models.json"`。新增 `openrouter_models_cache_file()` helper。
7. **模型表懒加载 + 3s 超时 + fail-open** —— `main.py:225-238` 启动序列严格不发网络请求，eager 拉取会破坏这个不变量。改为首次 `_infer_max_tokens` 需要时才拉，超时/失败自然回退到静态表。

## 背景与约束

OpenRouter 本身就是 OpenAI 兼容协议（`base_url=https://openrouter.ai/api/v1`），所以**今天就能用**——走现有的 `provider=openai` + 自定义 `base_url` 路径即可跑通。但有 4 个隐藏坑使得"能用"和"用得对"差距很大：

1. **`max_tokens` 推断失效** —— `_MAX_TOKENS_TABLE`（`config.py:35`）只认 `claude-*` / `qwen-*` 前缀（`/model` 命令 `commands.py:353, :447` 也调用 `_infer_max_tokens` 且不带 `provider`），OpenRouter 用命名空间 slug（`anthropic/claude-sonnet-4-5`）全部不命中，落到 `_FALLBACK_MAX_TOKENS = 8_192`，会截断 Sonnet/Opus 的长输出。
2. **`reasoning_effort` 被静默丢弃** —— `_openai_supports_reasoning_effort`（`llm.py:428`）的前缀检查不认 `openai/gpt-5` 这种带命名空间的名字。
3. **没有 attribution headers** —— OpenRouter 推荐 `HTTP-Referer` + `X-Title`，目前没注入。
4. **用不上 OpenRouter 的特色路由** —— `require_parameters`、`sort: throughput`、`models` fallback 数组等都没暴露。

OpenRouter 官方推荐的最佳实践（已 web 搜索 + 源码交叉验证）：

- **复用 OpenAI SDK**，只改 `base_url` + `default_headers` + `extra_body`，不要写新 backend
- **`require_parameters: true`** 必须默认开启 —— OpenRouter 自动只路由到真正支持 `tools` 的提供商，解决"模型不支持 function calling 导致 agent 挂掉"
- **交互式工具默认 `sort: "throughput"`** 而不是按价格选
- **`/api/v1/models` 端点**返回所有模型的真实 `top_provider.max_completion_tokens` —— 比手写前缀表更可靠，**注意是这个字段而不是 `context_length`**
- **`models` 数组**做 fallback —— 主模型挂了自动切，按实际使用计费
- **OpenAI Python SDK 的非标字段唯一入口是 `extra_body`** —— 顶层 kwargs 会被 Pydantic 校验后静默丢弃

```python
def _build_openai_chat_request(
    *,
    model: str,
    max_tokens: int,
    system: str | None,
    messages: list[dict[str, Any]],
    tools: list[dict[str, Any]],
    effort: str | None,
    stream: bool,
    extra_body_provider: dict[str, Any] | None = None,
    fallback_models: tuple[str, ...] = (),
) -> dict[str, Any]:
    params: dict[str, Any] = {
        "model": model,
        "messages": _to_openai_messages(system, messages),
        "max_tokens": max_tokens,
        "stream": stream,
    }
    if tools:
        params["tools"] = [_tool_schema_to_openai(t) for t in tools]
    if effort and _openai_supports_reasoning_effort(model):
        params["reasoning_effort"] = effort

    # OpenRouter 专有字段：必须走 SDK 的 extra_body 入口
    extra_body: dict[str, Any] = {}
    if extra_body_provider:
        extra_body["provider"] = extra_body_provider
    if fallback_models:
        extra_body["models"] = [model, *fallback_models]
    if extra_body:
        params["extra_body"] = extra_body

    return params
```

**新文件 `src/core/openrouter_models.py`**：

```python
"""OpenRouter Models 端点查询与本地缓存。

策略：
- 懒加载：首次需要时才发请求；启动期间不阻塞 REPL
- fail-open：网络/超时/解析失败一律返回 None，调用方自动回退到静态 _MAX_TOKENS_TABLE
- 24h TTL：超时后下次查询触发刷新
- 字段语义：读 top_provider.max_completion_tokens（输出上限），不是 context_length（总窗口）
"""

from __future__ import annotations

import json
import time
import urllib.request
from typing import Any

from .paths import ensure_dir, openrouter_models_cache_file

_MODELS_URL = "https://openrouter.ai/api/v1/models"
_CACHE_TTL_SEC = 24 * 60 * 60
_FETCH_TIMEOUT_SEC = 3.0  # 短超时，失败也不阻塞用户

_mem_cache: dict[str, int] | None = None
_mem_cache_at: float = 0.0


def _parse_models_payload(payload: Any) -> dict[str, int] | None:
    if not isinstance(payload, dict):
        return None
    raw_models = payload.get("data") or payload.get("models")
    if not isinstance(raw_models, list):
        return None
    out: dict[str, int] = {}
    for m in raw_models:
        if not isinstance(m, dict):
            continue
        mid = m.get("id")
        if not isinstance(mid, str):
            continue
        # 关键：top_provider.max_completion_tokens 是输出上限，不是 context_length
        top = m.get("top_provider") or {}
        mct = top.get("max_completion_tokens") if isinstance(top, dict) else None
        if isinstance(mct, int) and mct > 0:
            out[mid] = mct
    return out or None


def _read_disk() -> tuple[dict[str, int], float] | None:
    path = openrouter_models_cache_file()
    if not path.is_file():
        return None
    try:
        data = json.loads(path.read_text(encoding="utf-8"))
    except (OSError, json.JSONDecodeError):
        return None
    parsed = _parse_models_payload(data)
    if parsed is None:
        return None
    fetched_at = data.get("fetched_at") if isinstance(data, dict) else 0.0
    return parsed, float(fetched_at or 0.0)


def _fetch_remote() -> dict[str, int] | None:
    try:
        req = urllib.request.Request(_MODELS_URL, headers={"User-Agent": "Coco/0.1"})
        with urllib.request.urlopen(req, timeout=_FETCH_TIMEOUT_SEC) as resp:
            payload = json.loads(resp.read().decode("utf-8"))
    except Exception:
        return None
    return _parse_models_payload(payload)


def _save_disk(models: dict[str, int]) -> None:
    path = openrouter_models_cache_file()
    try:
        ensure_dir(path.parent)
        payload = {
            "fetched_at": time.time(),
            "data": [
                {"id": mid, "top_provider": {"max_completion_tokens": mt}}
                for mid, mt in models.items()
            ],
        }
        path.write_text(json.dumps(payload, ensure_ascii=False), encoding="utf-8")
    except OSError:
        pass


def lookup_max_completion_tokens(model_id: str) -> int | None:
    """查询某 OpenRouter 模型的输出上限；任何失败都返回 None（fail-open）。"""
    global _mem_cache, _mem_cache_at
    now = time.time()

    # 内存缓存有效
    if _mem_cache is not None and now - _mem_cache_at <= _CACHE_TTL_SEC:
        return _mem_cache.get(model_id)

    # 磁盘缓存
    disk = _read_disk()
    if disk is not None:
        cache, fetched_at = disk
        age = now - fetched_at
        if age <= _CACHE_TTL_SEC:
            _mem_cache, _mem_cache_at = cache, now
            return cache.get(model_id)
        # 磁盘缓存过期，先用着，同步尝试刷新
        _mem_cache, _mem_cache_at = cache, now
        fresh = _fetch_remote()
        if fresh:
            _mem_cache, _mem_cache_at = fresh, now
            _save_disk(fresh)
        return _mem_cache.get(model_id)

    # 没有任何缓存，发一次远程请求
    fresh = _fetch_remote()
    if fresh:
        _mem_cache, _mem_cache_at = fresh, now
        _save_disk(fresh)
        return fresh.get(model_id)

    return None
```

```python
def _infer_max_tokens(model: str, *, provider: Provider | None = None) -> int:
    """根据模型名前缀查表，未匹配时返回通用兜底值。

    OpenRouter 路径：先尝试动态查询 /v1/models，失败回退到静态表。

        try:
            from .openrouter_models import lookup_max_completion_tokens
            dynamic = lookup_max_completion_tokens(model)
            if dynamic:
                return dynamic
        except Exception:
            pass
    for prefix, limit in _MAX_TOKENS_TABLE:
        if model.startswith(prefix):
            return limit
    return _FALLBACK_MAX_TOKENS
```

### Step 5 — 已拆出本计划

REPL token + 成本展示是独立工作。Coco 当前 `main.py:_run_query`（`main.py:340-370`）拿到 `result.usage` 后**完全没有任何展示逻辑**——既没有单轮 token 显示，也没有跨轮累计。

## Summary

OpenRouter 接入 4 步全部完成。从"能跑"到"一等公民"：

1. **Step 1-2**（commit `c432222` / `ae6739c`）— 枚举、OpenAI backend 注入点、extra_body 机制、CLI / 提示文案
2. **Step 3**（本 commit）— 动态拉取 `/v1/models` 的真实 `max_completion_tokens`，失败 fail-open 到静态表
3. **Step 4**（本 commit）— `fallback_models` 配置层接入，严格 gate 在 OpenRouter 路径不泄漏给其他网关

**关键不变量**（贯穿 4 步）：

- OpenRouter 专有字段（`provider` 路由配置、`models` fallback 数组）**只走 `params["extra_body"]`**，绝不在顶层 kwargs（OpenAI SDK 的 Pydantic 校验会静默丢弃未知顶层字段）
- `pass_fallback_models=True` **只在 `Provider.OPENROUTER` 工厂分支设置**，DashScope / Qwen / 原生 OpenAI 等其他 OpenAI 兼容网关即便配了 `fallback_models` 也被代码忽略（不是依靠调用方自觉）
- `max_tokens` 的语义严格是"单次输出上限"，动态查询源是 `top_provider.max_completion_tokens`，绝不是 `context_length`
- 启动序列严格不发网络请求，动态查询懒触发，3 秒超时 + fail-open，最差情况回落到 Step 2 的静态前缀表

**未做的后续（有独立追踪）**：

- 成本回显（`usage.cost` 字段 + REPL token 展示）— 需要先有 REPL usage 展示载体，**拆成独立 session**
- 暴露 `provider` 路由的其他旋钮（`zdr` / `data_collection` / `max_price`）— 等用户反馈
- `coco openrouter --refresh-models` 手动刷新命令 — 暂时删缓存文件（`data_home() / "openrouter_models.json"`）等同触发
